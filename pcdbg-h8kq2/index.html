School PC debug kit

Read the limits, open the exe, run a tool — no install, no admin.

What this is

A locked school PC blocks a lot, but you can read exactly what it blocks and still run your own portable tools. Every box below has a Copy button. Paste it into PowerShell (not cmd) and press Enter.

Open PowerShell: press Win, type powershell, Enter. You do not need admin for any box here.

Why the exe would not open

In PowerShell a path that starts with a variable needs an & in front, and %USERPROFILE% is cmd syntax that PowerShell does not understand. A file you just downloaded also carries a "from the internet" mark that can stop it. The Open the exe tab fixes both.

The Tech-room scan on 24 Sep showed the PC is barely locked: FullLanguage, no AppLocker, every folder writable, Python 3.13 installed. Two real problems were left. The exe sits in Downloads, but the old box only looked in Documents, so it never launched it. And GOLDAUTOCLICKER is a Tauri app that draws its window with WebView2 — if WebView2 is missing, the exe starts and dies with no window. The Open the exe tab now checks both. If it is WebView2, do not fight it — the Autoclicker tab has the whole GOLDAUTOCLICKER rebuilt as a native window that needs no WebView2, so it shows and works the same.

Open the exe

Launch GOLDAUTOCLICKER and find out exactly why no window shows.

One box that opens it and says why

Finds the exe wherever it landed (Downloads first), strips the download mark, starts it, waits 5 seconds, then tells you: is the process still alive, does it have a window, and is WebView2 — the thing it draws its window with — on this PC.

open-goldautoclicker.ps1
$exe = Get-ChildItem "$env:USERPROFILE\Downloads","$env:USERPROFILE\Desktop","$env:USERPROFILE\Documents",$env:USERPROFILE -Recurse -Filter GOLDAUTOCLICKER.exe -ErrorAction SilentlyContinue | Select-Object -First 1 -ExpandProperty FullName if (-not $exe) { "NOT FOUND anywhere in your home"; return } "exe : $exe ($((Get-Item $exe).Length) bytes)" if (Get-Item $exe -Stream Zone.Identifier -ErrorAction SilentlyContinue) { "dl-mark : yes, removing it" } else { "dl-mark : none" } Unblock-File $exe -ErrorAction SilentlyContinue $wv = @('HKLM:\SOFTWARE\WOW6432Node','HKLM:\SOFTWARE','HKCU:\Software') | ForEach-Object { (Get-ItemProperty "$_\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}" -ErrorAction SilentlyContinue).pv } | Where-Object { $_ -and $_ -ne '0.0.0.0' } | Select-Object -First 1 if ($wv) { "webview2 : $wv" } else { "webview2 : MISSING" } $t0 = Get-Date try { $p = Start-Process $exe -PassThru -ErrorAction Stop } catch { "blocked : " + $_.Exception.Message; return } Start-Sleep -Seconds 5 $p.Refresh() if ($p.HasExited) { "process : DIED after start, exit code $($p.ExitCode)" } else { "process : alive, pid $($p.Id), window $($p.MainWindowHandle)" "children : " + @(Get-CimInstance Win32_Process -Filter "ParentProcessId=$($p.Id)" -ErrorAction SilentlyContinue).Count } Get-WinEvent -FilterHashtable @{LogName='Application'; StartTime=$t0} -ErrorAction SilentlyContinue | Where-Object { $_.Message -match 'GOLDAUTOCLICKER|WebView' } | Select-Object -First 3 | ForEach-Object { "event : " + ($_.Message -split "`n")[0] }

How to read it: webview2 MISSING + DIED = the exe is fine, this PC just lacks WebView2. blocked = the PC stopped it, the line says why. alive, window 0 = it started but the window is hidden. alive, window + a big number = it is open, check Alt+Tab.

If it says NOT FOUND

Your Documents may be redirected to the Z: drive. This searches your home, C: and Z: and prints the real full path so you can see where it landed.

find-exe.ps1
Get-ChildItem $env:USERPROFILE, C:\, Z:\ -Recurse -Filter GOLDAUTOCLICKER.exe -ErrorAction SilentlyContinue | Select-Object -First 1 -ExpandProperty FullName

The plain one-liner

On the Tech-room PC your copy is in Downloads, not Documents — that is why the old line said not recognized. The & is what makes PowerShell run it.

run.ps1
& "$env:USERPROFILE\Downloads\GOLDAUTOCLICKER.exe"

Machine limits

One read-only box that prints every restriction that matters.

Read what this machine allows

Pure read, all as a normal user. It tells you your integrity level, whether PowerShell is in the crippled Constrained mode, the script execution policy, and whether AppLocker is enforcing exe / script rules.

limits.ps1
"user : $env:USERNAME on $env:COMPUTERNAME" "home : $env:USERPROFILE" $admin = ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltinRole]::Administrator) "admin : $admin" "integrity : " + ((whoami /groups | Select-String 'Mandatory Level') -replace '\s+',' ') "langmode : $($ExecutionContext.SessionState.LanguageMode)" "" "-- execution policy --" Get-ExecutionPolicy -List | Format-Table -AutoSize | Out-String "-- applocker (blank = off) --" try { (Get-AppLockerPolicy -Effective).RuleCollections | ForEach-Object { "$($_.RuleCollectionType.PadRight(8)) $($_.EnforcementMode)" } } catch { "not readable" }

langmode other than FullLanguage means the machine cut PowerShell down — the autoclicker script tab will not run and you fall back to the exe. AppLocker Exe = Enabled means the exe is blocked unless it sits in an allowed folder (usually inside C:\Program Files or C:\Windows).

Writable folders

Find the folders you are allowed to write to and run from.

Where can you drop a tool

A portable tool has to live somewhere you can write to. This tries to create and delete a tiny file in each common folder and reports which ones let you.

writable.ps1
$dirs = @($env:TEMP, "$env:USERPROFILE\Documents", "$env:USERPROFILE\Downloads", $env:PUBLIC, $env:USERPROFILE, "C:\Windows\Temp") foreach ($d in $dirs) { $f = Join-Path $d ("w_" + [guid]::NewGuid().ToString("N") + ".txt") try { "x" | Out-File $f -ErrorAction Stop; Remove-Item $f -Force; "WRITE OK $d" } catch { "no write $d" } }

A folder that is WRITE OK but also AppLocker-allowed is where a portable exe will actually run. TEMP is almost always writable; whether an exe there runs depends on the AppLocker result from the Limits tab.

Python check

See if py / python can run your .py tools here.

Is Python usable

Your tools are .py, so this checks the py launcher and any python on PATH.

python-check.ps1
"-- py launcher --" try { py -3 --version } catch { "no py launcher" } "-- python on PATH --" $p = (Get-Command python -ErrorAction SilentlyContinue).Source if ($p) { $p; (Get-Item $p).Length } else { "no python on PATH" } "-- where --" where.exe python 2>$null where.exe py 2>$null

If python shows a Length of 0 it is the fake Windows Store stub — it opens the Store instead of running. Use py -3 instead, or a portable python you drop in a writable folder.

GOLDAUTOCLICKER, native window (no WebView2, no install, no admin)

The full clicker drawn by Windows itself instead of WebView2, so its window shows even on a PC that has no WebView2 — which is the thing that stops the .exe. Black-and-gold window, a big START / STOP button you click, a clicks-per-second box, and the same Ctrl+E toggle as the exe. No install, no admin. Paste it, put the mouse where you want, click START.

Fallback: console-only clicker (no window)

Same key as the exe: Ctrl+E starts and stops clicking wherever the cursor is, so you never Ctrl+C and paste again. Every re-paste recompiles the C# part, which is what made the PC stutter — this one compiles once and then just waits. The window title shows ON or OFF. Close the window to quit. Change $speed for faster or slower.

autoclicker.ps1
$speed = 100 # ms between clicks. 100 = 10 clicks a second $sig = '[DllImport("user32.dll")] public static extern void mouse_event(uint f,uint x,uint y,uint d,int e); [DllImport("user32.dll")] public static extern short GetAsyncKeyState(int k);' $m = Add-Type -MemberDefinition $sig -Name NgT -Namespace Click -PassThru $on = $false; $was = $false; $next = 0 $sw = [Diagnostics.Stopwatch]::StartNew() $host.UI.RawUI.WindowTitle = "clicker OFF - Ctrl+E on/off" "Ctrl+E = start / stop. Close this window to quit." while ($true) { $down = (($m::GetAsyncKeyState(0x11) -band 0x8000) -ne 0) -and (($m::GetAsyncKeyState(0x45) -band 0x8000) -ne 0) if ($down -and -not $was) { $on = -not $on; $next = $sw.ElapsedMilliseconds if ($on) { $host.UI.RawUI.WindowTitle = "clicker ON - Ctrl+E on/off" } else { $host.UI.RawUI.WindowTitle = "clicker OFF - Ctrl+E on/off" } } $was = $down if ($on -and $sw.ElapsedMilliseconds -ge $next) { $m::mouse_event(2,0,0,0,0); $m::mouse_event(4,0,0,0,0); $next = $sw.ElapsedMilliseconds + $speed } Start-Sleep -Milliseconds 5 }

If it errors with Add-Type is not supported in this language mode, the machine is in Constrained mode (see Limits). On the Tech-room PC it is FullLanguage, so it runs.

Everything in one paste

Next time you sit at the school PC, paste this one box first. It prints who you are, the language mode, execution policy, AppLocker, which folders are writable, whether py works, and whether WebView2 is installed — the whole picture in one go.

scan-all.ps1
$admin = ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltinRole]::Administrator) "user=$env:USERNAME admin=$admin langmode=$($ExecutionContext.SessionState.LanguageMode)" "integrity=" + ((whoami /groups | Select-String 'Mandatory Level') -replace '\s+',' ') Get-ExecutionPolicy -List | Format-Table -AutoSize | Out-String try { (Get-AppLockerPolicy -Effective).RuleCollections | ForEach-Object { "applocker $($_.RuleCollectionType)=$($_.EnforcementMode)" } } catch { "applocker not readable" } foreach ($d in @($env:TEMP,"$env:USERPROFILE\Documents",$env:PUBLIC)) { $f = Join-Path $d ("w_"+[guid]::NewGuid().ToString("N")+".txt") try { "x" | Out-File $f -ErrorAction Stop; Remove-Item $f -Force; "write ok $d" } catch { "no write $d" } } try { "py " + (py -3 --version 2>&1) } catch { "no py" } $wv = @('HKLM:\SOFTWARE\WOW6432Node','HKLM:\SOFTWARE','HKCU:\Software') | ForEach-Object { (Get-ItemProperty "$_\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}" -ErrorAction SilentlyContinue).pv } | Where-Object { $_ -and $_ -ne '0.0.0.0' } | Select-Object -First 1 if ($wv) { "webview2 $wv" } else { "webview2 MISSING" }
