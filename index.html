How to use

No key, no checkpoint, no ad link. Every control is a button. Drag it anywhere, mouse or finger.

Three steps

  1. Join the game and get into an arena round, not the lobby.
  2. Open your executor and paste the line.
  3. Press START FARM on the panel. It remembers your settings next time.

If nothing shows up

Run it while a round is live. In the lobby the script tells you and stops instead of throwing a wall of red text.

Any executor with loadstring and game:HttpGet works. gethui, readfile, writefile and hookfunction are optional — without them it still runs, it just forgets where you dragged the panel.

What the panel does

  • START FARM / STOP — the whole loop.
  • BACK — how far behind the target you stand. 0 works, so does 8.
  • BOTS / PLAYERS — pick what counts as a target.
  • RESPAWN — deploys you again the moment you die.
  • INF ONESHOT — fires the ultimate the moment it is charged, forever.
  • HOP SERVER — jumps to the fullest server it can find. More targets, more kills.

What it is

Seven Roblox clients on one desktop, split into three teams that run at the same time on three different servers: four on EggWars, two on Duos, one on Solo. Each team queues itself, parties itself, takes its own roll call, and plays without anyone touching a key.

The leader of the EggWars team is also a fighting bot. It kills, collects, upgrades its sword and buys, and still carries the party, the roll call and the rescue job for the other three.

The six layers

  • One entry point, not one file. Autoexec holds a single loader. It waits for the player, reads a roster, decides which role this client is, then loads the rest in order. It cannot be one file: the farm sits exactly on Luau's 200-local-register ceiling, so pasting the leader and the tick loop into it will not compile at all.
  • Identity is never hard-coded. The leader publishes its own name and UserId to a shared file on load; every other client reads it back. Bots recognise the leader by UserId, not by name, because a name can be changed and a farm that trusts names can be walked into.
  • Queue keeper. Every 5 seconds: if in the lobby, and able to queue, and not already queued, call joinQueue. The leader calls immediately, bots wait 45 s so the party can pull them in first.
  • Fighting does not wait for the game. The gate is the place, not the round state. In the match place with a body means work starts, with no waiting for the server to announce the round or to drop you on the floor.
  • Half-second self-check. Four questions every 0.5 s: did I move, did I pick anything up, did I kill anything, did I deal or take damage. Four no's means this bot is AFK no matter what the panel says, and a fixed ladder of recovery steps runs.
  • Recording. Every username and every chat line in the round, plus position and behaviour for anything unusual. 567 files and 42.4 MB so far.

Open source: BOOST

Seven Roblox clients on one machine pin the CPU at 100%. This is the whole file that brings it back down. Measured: 97.1% to 66.4% of total CPU across seven clients.

Frame rate is the one lever that cuts both sides at once. The picture is drawn per frame and the automation runs per frame, so halving the cap halves both.

BOOST.lua
-- BOOST - one per client, cuts the work each Roblox client does per frame. -- -- Measured on RAMST 2026-08-20 19:0x with seven clients up: the machine sat at -- 100% CPU, the seven together taking 1165% of one core out of the 1200% this -- i7-8700 has. RAM was never the problem, 11525 MB was free, and the GPU was at -- 55%. The wall is the CPU and nothing else. -- -- The one lever that cuts both halves of that at once is the frame rate, because -- rendering is per frame and so is every Heartbeat the farm runs. Everything else -- here is graphics work that costs CPU to draw pictures nobody is watching. -- -- The cap is read from RobloxComm/boost_fps.txt every few seconds rather than -- baked in, so it can be retuned across all seven clients by writing one file -- instead of reloading seven scripts. local RunService = game:GetService("RunService") local Lighting = game:GetService("Lighting") local Players = game:GetService("Players") -- A generation stamp in getgenv, and every loop below checks it before doing any -- work. STATE.alive() is supposed to be enough, and it is for one replacement, -- but measured at 19:2x on 2026-08-20 the cap was flipping 20, 30, 20, 30 every -- couple of seconds: an older copy of this script was still awake and still -- writing its own hardcoded number. A shared counter cannot be argued with - -- there is exactly one newest generation and everything else stops on its next -- tick, whatever put it there. getgenv().__BOOST_GEN = (getgenv().__BOOST_GEN or 0) + 1 local MY_GEN = getgenv().__BOOST_GEN local function mine() return getgenv().__BOOST_GEN == MY_GEN end local FPS_FILE = "RobloxComm/boost_fps.txt" local DEFAULT_FPS = 30 local EFFECTS = { ParticleEmitter = true, Trail = true, Beam = true, Smoke = true, Fire = true, Sparkles = true, Explosion = true, } local applied = -1 local function log(text) pcall(function() if not isfolder("RobloxComm") then makefolder("RobloxComm") end local who = Players.LocalPlayer and Players.LocalPlayer.Name or "?" local line = os.date("%Y-%m-%d %H:%M:%S") .. " " .. who .. " " .. tostring(text) .. "\n" local path = "RobloxComm/boost.log" if isfile(path) then appendfile(path, line) else writefile(path, line) end end) end local function wantedFps() local n pcall(function() if isfile(FPS_FILE) then n = tonumber((readfile(FPS_FILE):gsub("%s", ""))) end end) if not n or n < 5 or n > 240 then return DEFAULT_FPS end return math.floor(n) end -- Compare against what the cap actually is, not against what this script last -- asked for. The first version compared against its own last write and so gave up -- the moment anything else moved the cap - which is exactly what happened at -- 19:16 on 2026-08-20: the previous copy of this script was asleep inside its own -- five second wait when the reload replaced it, woke once more, wrote 30 over the -- new 20, and then exited. Every client logged "fps cap now 20" and every client -- was really running at 30. Reading the live value makes that self-correcting, -- and also means Vape or the game can never quietly take the cap back. local function capFps() local want = wantedFps() local live = -1 pcall(function() if getfpscap then live = getfpscap() end end) if live == want then applied = want return end pcall(function() if setfpscap then setfpscap(want) end end) if applied ~= want then applied = want log("fps cap now " .. want) end end local function lowQuality() pcall(function() settings().Rendering.QualityLevel = Enum.QualityLevel.Level01 end) pcall(function() local ugs = UserSettings():GetService("UserGameSettings") ugs.SavedQualityLevel = Enum.SavedQualitySetting.QualityLevel1 ugs.MasterVolume = 0 end) pcall(function() Lighting.GlobalShadows = false Lighting.FogEnd = 1e6 Lighting.EnvironmentDiffuseScale = 0 Lighting.EnvironmentSpecularScale = 0 end) for _, child in ipairs(Lighting:GetChildren()) do if child:IsA("PostEffect") then pcall(function() child.Enabled = false end) end end local terrain = workspace:FindFirstChildOfClass("Terrain") if terrain then pcall(function() terrain.WaterWaveSize = 0 terrain.WaterWaveSpeed = 0 terrain.WaterReflectance = 0 terrain.WaterTransparency = 0 terrain.Decoration = false end) end end -- One walk of the tree, spread over frames so the walk itself does not become the -- stutter it is meant to remove. After this the DescendantAdded hook is enough: -- anything new gets caught as it arrives for the cost of one class lookup. local function sweep() local killed = 0 local seen = 0 for _, inst in ipairs(workspace:GetDescendants()) do seen = seen + 1 if EFFECTS[inst.ClassName] then pcall(function() inst.Enabled = false end) killed = killed + 1 end if seen % 2000 == 0 then task.wait() end end return seen, killed end capFps() lowQuality() task.spawn(function() local seen, killed = sweep() if not mine() then return end log(string.format("boost gen %d on: quality 1, %d effects off out of %d instances", MY_GEN, killed, seen)) end) STATE.connect(workspace.DescendantAdded, function(inst) if EFFECTS[inst.ClassName] then pcall(function() inst.Enabled = false end) end end) -- Re-assert rather than set once. A teleport between the lobby and a match builds -- a new DataModel and the quality level comes back with it. The cost is four -- property writes every three seconds and no traversal at all. task.spawn(function() while STATE.alive() and mine() do task.wait(3) if not mine() then return end capFps() lowQuality() end end) -- No setfpscap(0) on cleanup. A reload tears the old copy down and builds the new -- one, and an uncap in between is a spike on a machine that has no headroom for -- one. The incoming copy sets the cap on its first line anyway. STATE.onCleanup(function() end) return "BOOST active, reading " .. FPS_FILE

Open source: the group loader

One script per team. It loads the combat library first, then the boost, then the farm, and it reports a missing file by name rather than skipping it in silence, because a farm that quietly did not load looks exactly like a farm that loaded and did nothing, and that is the failure that costs a whole night.

Account identifiers are replaced with placeholders here.

GROUP_ABCD_EGG.lua
-- GROUP_ABCD_EGG - the four EggWars accounts -- -- One script for the whole ABCD EGG group. His call on 2026-08-20: -- "it was only one scirpt execute only to the whole group as tha tmkae sure each -- group have vape mean u nee to put the script of vape ... into that so it was -- allow to using vape and others scirpt at the same loading". -- -- So Vape is not a separate thing to remember any more. It is the first line of -- the group's own loader, and everything else the group needs follows it in this -- one file. Execute this, and that account has all of it. -- -- Accounts in this group: -- D <D-ACCOUNT> <D-NAME> leader -- A <A-ACCOUNT> <A-NAME> -- B <B-ACCOUNT> <B-NAME> -- C <C-ACCOUNT> <C-NAME> -- -- What it loads, in order: -- 1. Vape V4 -- 2. BOOST -- 3. EggWars farm local Players = game:GetService("Players") local lp = Players.LocalPlayer local LOG = "RobloxComm/group_load.log" local GROUP = "ABCD EGG" local function say(text) pcall(function() if not isfolder("RobloxComm") then makefolder("RobloxComm") end local who = "?" if lp then who = lp.Name end local line = os.date("%Y-%m-%d %H:%M:%S") .. " " .. GROUP .. " " .. who .. " " .. tostring(text) .. "\n" if isfile(LOG) then appendfile(LOG, line) else writefile(LOG, line) end end) print("[" .. GROUP .. "] " .. tostring(text)) end say("loader start") -- Vape first, because everything after it expects the combat modules to exist. -- The line is his, copied exactly as he wrote it. local vapeOk, vapeErr = pcall(function() loadstring(game:HttpGet("https://rawscripts.net/raw/Vape-V4-For-Roblox_316"))() end) if vapeOk then say("vape loaded") else say("vape FAILED: " .. tostring(vapeErr)) end -- Everything else is a file in Real's workspace. A missing one is reported by -- name rather than skipped in silence - a farm that quietly did not load looks -- exactly like a farm that loaded and did nothing, and that is the failure that -- costs a whole night. local FILES = { { name = "BOOST", file = "BOOST.lua" }, { name = "EggWars farm", file = "FARM_SKYWARS_ABCD.lua" }, } for _, step in ipairs(FILES) do if not isfile(step.file) then say(step.name .. " NOT LOADED - " .. step.file .. " is not written yet") else local chunk, cerr = loadstring(readfile(step.file), "=" .. step.file) if not chunk then say(step.name .. " FAILED TO COMPILE: " .. tostring(cerr)) else local ok, rerr = pcall(chunk) if ok then say(step.name .. " loaded") else say(step.name .. " ERROR: " .. tostring(rerr)) end end end end say("loader done") return GROUP .. " loader finished"

Page 7 — the eye page

Dark mode, night shift, true tone, and five brightness steps.

  • The dimming bends the display gamma curve instead of touching the backlight, so a PWM panel cannot start flickering at low brightness — which is the usual reason dimming makes eyes feel worse, not better.
  • A plain multiply gets refused: Windows rejects any ramp entry sitting more than 32768 away from the straight line, and warm plus dim together blows straight past it. A power curve drops the midtones hard while the white point barely moves, so it reads much darker and every entry stays legal.
  • The table is read back once a second and only rewritten when something else replaced it. Going fullscreen in a game does not quietly switch it off, and there is no flicker from writing a value that is already there.

Things it does that are easy to get wrong

  • The panel pushes itself to the bottom of the window order every three seconds. “It did not open” is usually “it opened and it is buried” — look for a pythonw process before you believe it failed.
  • Every failure is printed on the panel itself. Nothing here reports success into a console you are not watching.
  • The priority sweep runs on a worker thread. One pass across 383 processes costs 19 ms, and a panel that spends that on its own UI thread every second is a panel that causes the lag it was added to remove.
  • A single-instance mutex means a second copy exits rather than drawing a second panel.
