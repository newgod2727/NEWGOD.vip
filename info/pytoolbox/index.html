First run — press START.cmd, not the .py

Downloading this and getting nothing is the normal outcome, and none of the reasons announce themselves. So the zip now carries START.cmd, and that is the thing to press. It finds a Python, installs psutil if it is missing, refuses to run out of a zip preview folder, starts the panel with pythonw.exe, and then goes and finds the panel’s own window to prove it is up. Whatever happens, it writes it in plain English into FIRST-RUN.txt next to itself.

START.cmd bootstrap.py

The four ways a download does nothing

  • psutil is missing. This is the silent one. import psutil is on line 32 and the log file is not opened until line 37, so the panel dies before it can write a single line — no window, no log, no error, exit code 1. Measured. Fix: pip install psutil, or just let START.cmd do it.
  • There is no Python, but it looks like there is. On a clean Windows, python.exe exists as a 0-byte Microsoft Store alias, so where python finds it and running it opens the Store instead. There is no pythonw.exe alias at all. START.cmd skips anything 0 bytes and tells you what to install.
  • It was run from inside the zip window. Windows extracts to a temp folder, the panel really does start, and then the whole folder disappears the moment the zip window closes — taking the log and the settings with it. Extract properly first; START.cmd refuses to run from there.
  • It started and you cannot see it. It is under everything, by design. Sweep the pointer into the left edge of the screen — see Easy to get wrong.

One more that is not a failure: run a second copy and it exits quietly after about eight seconds, because a single-instance mutex already belongs to the first one. The log says so in words.

Every feature on page 1

Page 1 of the panel is a launcher, and every row on it starts a separate tool that lives in its own file. Pick a row and take that one file on its own.

Read this once, then never again

  • Every .py below wants Python 3.12 and psutil. The one .exe wants nothing at all — no Python, no install.
  • The downloaded file has to sit in the same folder as toolbox.py. A panel row starts its tool by filename out of its own folder, so a file left in Downloads is a row that does nothing when you press it.
  • Start a .py with pythonw.exe, never python.exe. python.exe leaves a black console window sitting on the screen for as long as the tool runs.

Page 7 — the eye page

Dark mode, night shift, true tone, and five brightness steps.

Why it bends the gamma instead of the backlight

  • The dimming bends the display gamma curve instead of touching the backlight, so a PWM panel cannot start flickering at low brightness — which is the usual reason dimming makes eyes feel worse, not better.
  • A plain multiply gets refused: Windows rejects any ramp entry sitting more than 32768 away from the straight line, and warm plus dim together blows straight past it. A power curve drops the midtones hard while the white point barely moves, so it reads much darker and every entry stays legal.
  • The table is read back once a second and only rewritten when something else replaced it. Going fullscreen in a game does not quietly switch it off, and there is no flicker from writing a value that is already there.

Things it does that are easy to get wrong

Four behaviours that look like bugs until you know they are deliberate.

The four

  • The panel lives under every other window on purpose, and it comes up when you reach for it: put the pointer into the first three columns of pixels at the left edge of the screen. Nobody guesses that. “It did not open” is almost always “it opened, it is underneath, and I did not know the gesture” — sweep the left edge, then look for a pythonw process, before you believe it failed. While a game is running the reveal is suppressed on purpose, because a topmost window over a fullscreen game costs frames.
  • Every failure is printed on the panel itself. Nothing here reports success into a console you are not watching.
  • The priority sweep runs on a worker thread. One pass across 383 processes costs 19 ms, and a panel that spends that on its own UI thread every second is a panel that causes the lag it was added to remove.
  • A single-instance mutex means a second copy exits rather than drawing a second panel.
